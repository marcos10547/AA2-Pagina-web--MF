Enrutador (Router)

Tienda (Pinia)
¿Qué operaciones implementa tu store de Pinia para este módulo?
✨ Haz clic para ver la respuesta técnica...
Tienda (Pinia)
En stores/reservation.ts centralizamos el estado en un array reactivo reservations y definimos 4 operaciones asíncronas:

1. fetchReservations(): Realiza un GET a la API.
2. addReservation(): Hace un POST con el formulario y actualiza el estado local con .push().
3. updateReservationStatus(): Envía un PUT para cambiar el estado (confirmar/cancelar).
4. deleteReservation(): Envía un DELETE y remueve la reserva con .filter().

Vistas y Validación
Para evitar hacer llamadas innecesarias de red al servidor. Al montar la vista de ReservationList.vue, cargamos todas las reservas de la base de datos una sola vez.

Arquitectura / DB
¿Cómo se comunican el Frontend SPA y el Backend API en este proyecto?
✨ Haz clic para ver la respuesta técnica...
Arquitectura / DB
Siguen una arquitectura desacoplada. El frontend corre en el navegador e inicia llamadas asíncronas HTTP (mediante el API estándar fetch de JavaScript) hacia el servidor API local de Express configurado por la variable de entorno VITE_API_URL (puerto 3000 por defecto).

El backend recibe las peticiones, realiza validaciones, comprueba tokens de seguridad, ejecuta sentencias sobre PostgreSQL y responde enviando objetos de datos en formato JSON.

Vistas y Validación
Siguiendo las restricciones de "no utilizar alertas del sistema (alert)", la aplicación implementa notificaciones mediante un Snackbar de Vuetify.

Arquitectura / DB
¿Cómo se garantiza la persistencia física y seguridad de las reservas?
✨ Haz clic para ver la respuesta técnica...
Arquitectura / DB
La tabla reservations está definida en PostgreSQL en [init.sql] con clave primaria auto-incremental, campos mandatorios y valores por defecto (status pendiente).

Para garantizar la seguridad, el backend realiza consultas parametrizadas seguras (mediante placeholders $1, $2, ... de la librería pg) lo que mitiga e impide al 100% ataques de Inyección SQL al procesar textos enviados por clientes maliciosos en inputs libres (como las notas de la reserva).

Conceptos Vue 3
Es el modelo moderno de estructuración de componentes de Vue 3. La etiqueta <script setup> es azúcar sintáctico que simplifica el desarrollo e incrementa el rendimiento.

Nos permite declarar el estado asíncrono, variables reactivas, funciones y componentes importados directamente en el bloque script, haciéndolos disponibles de forma automática para el template HTML sin necesidad de exportaciones explícitas o de usar un bloque return (como en la clásica Options API).
Conceptos Vue 3
¿Cuál es la diferencia técnica entre ref() y computed()?
✨ Haz clic para ver la respuesta técnica...
Conceptos Vue 3
ref() define un estado reactivo base y mutable (cualquier tipo de datos). En JavaScript accedemos/modificamos su valor usando .value, y en el template de Vue se desenvuelve de forma automática sin el sufijo.

computed() genera una propiedad reactiva derivada de otros estados. Es de solo lectura y tiene un mecanismo de caché interno: solo se vuelve a ejecutar si alguna de las dependencias reactivas que contiene en su función cambia, ahorrando ciclos de CPU y renderizados.
Conceptos Vue 3
¿Qué es onMounted() y para qué se utiliza en este módulo?
✨ Haz clic para ver la respuesta técnica...
Conceptos Vue 3
Es un gancho del ciclo de vida (Lifecycle Hook) de Vue 3.

Se ejecuta automáticamente una única vez justo después de que el componente ha terminado su renderizado inicial y su nodo del DOM físico ha sido insertado en el navegador. Es el momento perfecto para cargar datos desde servicios externos, por lo que en ReservationList.vue lo usamos para disparar la acción fetchReservations() de Pinia y alimentar nuestra tabla.
Conceptos Vue 3
¿Cómo se comunican tus componentes mediante Props y Emits?
✨ Haz clic para ver la respuesta técnica...
Conceptos Vue 3
Sigue el flujo unidireccional de datos de Vue (Props Down, Events Up).

El componente padre (ReservationList.vue) le transfiere variables al componente hijo mediante Props (atributos con prefijo :). A su vez, el hijo (ReservationForm.vue) utiliza defineEmits para declarar eventos de salida. Al guardar la reserva, el hijo ejecuta emit('save', datos), gatillando el método asíncrono onSave en el padre para registrar los datos.
Conceptos Vue 3
¿Qué es y cómo funciona el doble enlace de datos (v-model)?
✨ Haz clic para ver la respuesta técnica...
Conceptos Vue 3
v-model proporciona Two-way Data Binding (doble enlace de datos en tiempo real) en elementos de formulario.

Es un atajo de Vue que combina dos acciones: pasa el valor de una variable reactiva de JavaScript al atributo value del input del navegador (prop), y a la vez escucha el evento input del elemento para actualizar automáticamente la variable cuando el usuario escribe. Permite mantener sincronizados en todo momento los inputs del usuario con el estado del componente.
Tienda (Pinia)
¿Qué es Pinia y por qué se prefiere al estado local en aplicaciones reales?
✨ Haz clic para ver la respuesta técnica...
Tienda (Pinia)
Pinia es el gestor oficial de estado centralizado para Vue 3. En proyectos reales, múltiples vistas y layouts necesitan compartir y modificar la misma información (como la sesión del usuario o las reservas actuales).

Si usáramos estado local en componentes, tendríamos que pasar datos y eventos a través de muchos niveles jerárquicos (Prop Drilling), haciendo el código rígido y propenso a errores. Pinia crea un almacén centralizado e independiente que cualquier componente puede inyectar y escuchar reactivamente en tiempo real.
Tienda (Pinia)
¿Cuáles son las tres partes fundamentales de un Store en Pinia?
✨ Haz clic para ver la respuesta técnica...
Tienda (Pinia)
Un Store de Pinia se define con defineStore y consta de:

1. State: Una función que retorna un objeto con las variables reactivas (datos en memoria, ej. reservations: []). Equivale al ref().
2. Actions: Métodos (síncronos o asíncronos) que contienen la lógica de negocio y las llamadas a la API para modificar el state (ej. fetchReservations()). Equivale a funciones.
3. Getters: Propiedades computadas basadas en el state. Tienen memoria caché (ej. obtener reservas pendientes). Equivale al computed().
Tienda (Pinia)
¿Qué stores tiene este proyecto y de qué se encarga cada uno?
✨ Haz clic para ver la respuesta técnica...
Tienda (Pinia)
Tu proyecto implementa 5 stores modulares en frontend/src/stores/:

- auth.ts: Gestiona la sesión del usuario (token JWT, roles, inicio/cierre de sesión).
- reservation.ts: Mantiene las reservas reactivas y se comunica con los endpoints HTTP (CRUD).
- ui.ts: Controla el estado visual global, como notificaciones Snackbar y spinners de carga.
- product.ts y vendor.ts: Gestionan respectivamente el catálogo de productos y los proveedores de la cafetería.
Tienda (Pinia)
¿Cómo cooperan el store de reservas (reservation.ts) y el store de interfaz (ui.ts)?
✨ Haz clic para ver la respuesta técnica...
Tienda (Pinia)
Se comunican e integran de forma reactiva en la vista. Por ejemplo, en ReservationList.vue, cuando el usuario completa el formulario, la vista invoca la acción reservationStore.addReservation().

Si la promesa HTTP se resuelve con éxito, la vista invoca inmediatamente a uiStore.showNotify('Reserva creada', 'success'). Esto delega la respuesta visual al store de UI sin mezclar la lógica de datos con la lógica visual, manteniendo el código limpio y modular.
Tienda (Pinia)
¿Cómo se extraen datos de un Store de Pinia en Vue 3 sin perder la reactividad?
✨ Haz clic para ver la respuesta técnica...
Tienda (Pinia)
Si en el script de Vue destructuramos el store de forma directa: const { reservations } = reservationStore, se rompe la reactividad de inmediato y la interfaz no se redibujará cuando los datos cambien.

Para mantener la reactividad al extraer datos, debemos envolver el store en el helper storeToRefs de Pinia: const { reservations } = storeToRefs(reservationStore).
Nota: Las acciones son funciones y no contienen estado reactivo, por lo que se pueden desestructurar directamente.
